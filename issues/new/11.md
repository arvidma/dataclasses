# slots=True breaks zero-argument super() in methods

## Severity: MEDIUM

## Description

`_add_slots()` must create a brand-new class (since `__slots__` cannot
be added after class creation).  Methods defined in the class body,
however, carry a `__class__` closure cell that still points at the
**old** class.  Zero-argument `super()` uses that cell, so it receives
a class the instance is not an instance of.

## Reproduction (verified)

```python
@dataclass(slots=True)
class D:
    x: int
    def show(self):
        return super().__str__()

D(1).show()
# TypeError: super(type, obj): obj must be an instance or subtype of type
```

Any use of `super()` or `__class__` inside a method of a
`slots=True` dataclass fails the same way.

## CPython 3.12+ (reference)

CPython fixed this in gh-90562 by patching the `__class__` cell of
every function (and property accessor) in the new class:

```python
def _update_func_cell_for__class__(f, oldcls, newcls):
    # Returns True if we update a cell, else False.
    if f is None:
        # Functions in a class namespace can be None.
        return False
    try:
        idx = f.__code__.co_freevars.index("__class__")
    except ValueError:
        # This function doesn't reference __class__, so nothing to do.
        return False
    ...
```

and in `_add_slots()`:

```python
    # Fix up any closures which reference __class__.  This is used to
    # fix zero argument super so that it points to the correct class
    # (the newly created one, which we're returning) and not the
    # original class.
    for member in newcls.__dict__.values():
        # If this is a wrapped function, unwrap it.
        member = getattr(member, '__wrapped__', member)
        if isinstance(member, types.FunctionType):
            _update_func_cell_for__class__(member, cls, newcls)
        elif isinstance(member, property):
            ...
```

## Impact

Silent divergence from the stdlib for a backported feature the readme
lists as fully "Backported" (`slots` parameter, 3.10).  Classes using
inheritance plus `slots=True` are especially likely to hit this.

This gap is not listed in the readme's feature matrix.

## Sources

- gh-90562: https://github.com/python/cpython/issues/90562
- CPython 3.12+ `Lib/dataclasses.py`,
  `_update_func_cell_for__class__()` and `_add_slots()`

## Proposed resolution

Backport `_update_func_cell_for__class__()` and the fix-up loop in
`_add_slots()` from CPython 3.12, and add a test that calls
zero-argument `super()` from a method of a `slots=True` dataclass
(see issue 14).  Alternatively, document it as a known limitation in
the readme matrix.
