# asdict()/astuple() crash on namedtuple values

## Severity: HIGH

## Description

`_asdict_inner()` and `_astuple_inner()` reconstruct list/tuple
containers with `type(obj)(generator)`:

```python
elif isinstance(obj, (list, tuple)):
    return type(obj)(_asdict_inner(v, dict_factory) for v in obj)
```

A namedtuple is a tuple subclass, but its constructor takes positional
arguments, not a single iterable. Passing a generator therefore raises
`TypeError`.

## Reproduction (verified)

```python
from collections import namedtuple
NT = namedtuple("NT", "a b")

@dataclass
class C:
    p: object

asdict(C(NT(1, 2)))
# TypeError: NT.__new__() missing 1 required positional argument: 'b'
```

`astuple()` fails the same way.

## CPython (reference)

CPython special-cases namedtuples (bpo-34363) in both
`_asdict_inner()` and `_astuple_inner()`:

```python
elif issubclass(obj_type, tuple):
    if hasattr(obj, '_fields'):
        # obj is a namedtuple.  Recurse into it, but the returned
        # object is another namedtuple of the same type. ...
        return obj_type(*[_asdict_inner(v, dict_factory) for v in obj])
```

## Impact

Any dataclass whose (possibly nested) field values contain a
namedtuple cannot be converted with `asdict()`/`astuple()`.  This is a
silent behavioral gap relative to the stdlib: code working with the
real `dataclasses` module breaks when the backport is substituted.

This gap is also not listed in the readme's feature matrix.

## Sources

- bpo-34363: https://bugs.python.org/issue34363
- CPython `Lib/dataclasses.py`, `_asdict_inner()` / `_astuple_inner()`

## Proposed resolution

Backport the namedtuple branch (`isinstance(obj, tuple) and
hasattr(obj, '_fields')` → `type(obj)(*[...])`) into both
`_asdict_inner()` and `_astuple_inner()`, and add tests covering
namedtuple values in `asdict()` and `astuple()` (see issue 14).
