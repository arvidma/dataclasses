# Test coverage gaps

## Severity: LOW

## Description

The suite in `test.py` has good breadth (~200 checks covering all
backported features and many corner cases), but several code paths in
`dataclasses.py` — including some of the trickiest — have no coverage
at all.

## Missing coverage

1. **String annotations.**  The entire `_is_type()` regex machinery
   (`_MODULE_IDENTIFIER_RE`, module-lookup logic) exists solely to
   detect `ClassVar`, `InitVar` and `KW_ONLY` given as *string*
   annotations, and none of it is exercised.  No test uses:

   ```python
   cv: "typing.ClassVar[int]" = 0
   iv: "InitVar[int]" = 0
   _: "KW_ONLY"
   ```

   including the documented corner cases in the `_is_type()` comments
   (module-aliased forms like `"dataclasses.InitVar[int]"`).

2. **Descriptor defaults / `__set_name__`.**  The PEP 487 path in
   `Field.__set_name__()` (a field whose default value is a
   descriptor) is untested.

3. **The gaps found in issues 10 and 11** (namedtuple values in
   `asdict()`/`astuple()`, zero-argument `super()` under
   `slots=True`) had no tests — unsurprising, since untested corners
   are where gaps survive.  Regression tests should accompany those
   fixes.

4. **`_create_fn()` closure semantics and `_return_type` renaming**
   (issues 2 and 3) were fixed without regression tests.  A field
   named `__dataclass_return_type__`-adjacent (or simply
   `_return_type`) with a default would pin the behavior.

## Precision issues

Several `check_raises` calls accept a union of exception types where
CPython's behavior is exact, e.g.:

```python
check_raises(
    "replace init=False field raises",
    (TypeError, ValueError),
    lambda: replace(rif, x=2, y=30),
)
```

CPython raises `ValueError` here; accepting `TypeError` too means a
behavior change would pass silently.  The same pattern appears for the
required-InitVar `replace()` tests and the frozen `replace()` tests.

## Structural note (no action required)

The homegrown `check`/`check_raises` harness instead of `unittest`
(available on 3.6) is a defensible simplicity choice, but note it has
no test isolation: a module-level error in any section aborts the
whole run.

## Proposed resolution

- Add tests for string-annotation detection of ClassVar, InitVar and
  KW_ONLY (both bare and module-qualified forms).
- Add a `__set_name__` descriptor-default test.
- Add regression tests together with the fixes for issues 10 and 11.
- Tighten `check_raises` unions to the exact exception CPython raises.
