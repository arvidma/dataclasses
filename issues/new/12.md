# Feature matrix missing 3.13 __replace__ / copy.replace() row

## Severity: LOW

## Description

Python 3.13 added a `__replace__()` method to dataclasses so that they
work with the new `copy.replace()` protocol (gh-108751).  In CPython
3.13+, `dataclasses.replace()` delegates to the same underlying
implementation and every dataclass gets:

```python
    _set_new_attribute(cls, '__replace__', _replace)
```

The backport implements neither `__replace__` nor `copy.replace()`
support, which is a reasonable scoping decision (on Python 3.6 there
is no `copy.replace()` to integrate with), but the readme's feature
matrix does not mention it.  The matrix currently ends its
"Not backported" section with:

```
| 3.12 | `module` parameter for `make_dataclass()` | Not backported |
| 3.12 | `defaultdict` support in `asdict()`/`astuple()` | Not backported |
```

The matrix otherwise covers features through 3.14 (the
`make_dataclass(decorator=...)` parameter), so the 3.13 `__replace__`
omission looks like an oversight rather than a decision.

## Impact

Documentation completeness only.  Readers auditing what they get
relative to a modern stdlib cannot tell whether `__replace__` was
considered.

## Sources

- gh-108751: https://github.com/python/cpython/issues/108751
- CPython 3.13 `Lib/dataclasses.py`, `_replace()` and
  `_process_class()`
- readme.md, feature matrix

## Proposed resolution

Add a row to the matrix:

```
| 3.13 | `__replace__()` method (`copy.replace()` support) | Not backported |
```

(or backport the method itself — it is small and self-contained — in
which case mark it "Backported").
