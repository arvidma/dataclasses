# No CI — the test suite is effectively never run

## Severity: MEDIUM

## Description

`test.py` hard-exits unless the interpreter is exactly Python 3.6:

```python
if sys.version_info[:2] != (3, 6):
    print(
        f"ERROR: These tests require Python 3.6, got {sys.version_info[0]}.{sys.version_info[1]}"
    )
    sys.exit(1)
```

The repository has no CI configuration of any kind, and Python 3.6 is
EOL and absent from typical developer machines.  In practice this
means the test suite is rarely (possibly never) executed, and
regressions — including the total breakage on 3.7+ described in
issue 9 — go undetected.

## Impact

- Changes to `dataclasses.py` land without any automated verification.
- The version pin plus missing CI mutually reinforce: nobody has a
  3.6 handy, so nobody runs the tests, so the pin is never felt.

## Proposed resolution

Add a GitHub Actions workflow that runs the suite in a Python 3.6
container, e.g.:

```yaml
name: tests
on: [push, pull_request]
jobs:
  test-py36:
    runs-on: ubuntu-latest
    container: python:3.6-slim
    steps:
      - uses: actions/checkout@v4
      - run: python test.py
```

If issue 9 is resolved by making the module work on 3.7+, extend the
matrix to those versions as well (relaxing the version check in
`test.py` accordingly, ideally with expected-behavior branches where
3.6 and 3.7+ legitimately differ).

Optionally also run `ruff check` and `mypy --strict` in CI on a modern
Python, since the repo already targets both (commits b0f75bf and
bfec23e).
