# Module unusable on Python 3.7+ due to typing._ClassVar

## Severity: HIGH

## Description

`_is_classvar()` detects ClassVar annotations via the typing-internal
class `typing._ClassVar`:

```python
def _is_classvar(a_type: Any, typing: Any) -> bool:
    # This test uses a typing internal class, but it's the best way to
    # test if this is a ClassVar.
    return type(a_type) is typing._ClassVar
```

`typing._ClassVar` only exists in Python 3.6. It was removed in
Python 3.7 when `ClassVar` became a `_SpecialForm` and subscripted
forms became `_GenericAlias` instances.

Because this module imports `typing` at the top (so `typing` is always
present in `sys.modules`), `_is_classvar()` is called for **every**
field of **every** dataclass. On Python 3.7+ this raises
`AttributeError: module 'typing' has no attribute '_ClassVar'` for any
`@dataclass` definition — even ones with no ClassVar fields at all.

## Reproduction (verified on Python 3.11)

```python
import dataclasses  # this backport

@dataclasses.dataclass
class A:
    x: int
# AttributeError: module 'typing' has no attribute '_ClassVar'
```

## Why this matters

The readme claims the module "can transparently replace the stdlib if
running on a Python version that doesn't support some feature you
like", and the usage example uses a try/except ImportError fallback:

```python
try:
    from dataclasses import dataclass, field, KW_ONLY
except ImportError:
    from myproj.vendor.dataclasses import dataclass, field, KW_ONLY
```

On Python 3.7–3.9 the stdlib import fails (no `KW_ONLY`), the fallback
is taken, and the vendored module then crashes at class-definition
time. The documented use case is broken on every version except 3.6.

## CPython 3.7+ (reference)

```python
def _is_classvar(a_type, typing):
    # This test uses a typing internal class, but it's the best way to
    # test if this is a ClassVar.
    return (a_type is typing.ClassVar
            or (type(a_type) is typing._GenericAlias
                and a_type.__origin__ is typing.ClassVar))
```

(The original ericvsmith 3.6 backport used `typing._ClassVar`, which
this module inherited.)

## Proposed resolution

Either:

1. Make `_is_classvar()` version-tolerant, e.g.:

   ```python
   def _is_classvar(a_type, typing):
       if hasattr(typing, "_ClassVar"):
           # Python 3.6
           return type(a_type) is typing._ClassVar
       # Python 3.7+
       return (a_type is typing.ClassVar
               or (type(a_type) is typing._GenericAlias
                   and a_type.__origin__ is typing.ClassVar))
   ```

   and add tests that run on modern Python (see issue 13), or

2. Declare in the readme that the module works **only** on Python 3.6,
   and remove/reword the "transparently replace the stdlib" claim and
   the fallback-import example.

Option 1 is preferred: it matches the stated purpose and is a small,
well-understood change.
