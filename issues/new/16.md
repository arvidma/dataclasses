# dataclass() docstring omits backported parameters

## Severity: INFO

## Description

The `dataclass()` docstring describes the original 3.7 parameters plus
`kw_only`, but never mentions `match_args`, `slots` or `weakref_slot`
— the very features this backport exists to provide:

```python
    """Returns the same class as was passed in, with dunder methods
    added based on the fields defined in the class.

    Examines PEP 526 __annotations__ to determine fields.

    If init is true, an __init__() method is added to the class. If
    repr is true, a __repr__() method is added. If order is true, rich
    comparison dunder methods are added. If unsafe_hash is true, a
    __hash__() method function is added. If frozen is true, fields may
    not be assigned to after instance creation. If kw_only is true, then
    by default all fields are keyword-only.
    """
```

## CPython 3.12+ (reference)

```python
    """...
    If frozen is true, fields may not be assigned to after instance
    creation. If match_args is true, the __match_args__ tuple is added.
    If kw_only is true, then by default all fields are keyword-only.
    If slots is true, a new class with a __slots__ attribute is
    returned.
    """
```

CPython's docstring covers `match_args` and `slots` (and `eq`, which
the backport's version also skips); `weakref_slot` is worth a sentence
too since users on 3.6 have no stdlib docs for it.

## Proposed resolution

Extend the docstring to cover `eq`, `match_args`, `slots` and
`weakref_slot`, following CPython's wording where it exists.
