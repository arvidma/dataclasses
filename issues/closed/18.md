# The ruff config buys 3.6 safety by turning almost all of ruff off

## Severity: LOW

## Description

When ruff 0.16.0 broke the lint job (issue 13, follow-up section),
`ruff.toml` was added to stop the bleeding:

```toml
target-version = "py37"

[lint]
select = ["E4", "E7", "E9", "F"]
```

That works, but it is a blunt instrument.  `E4`/`E7`/`E9`/`F` is
roughly "pyflakes plus a few syntax-adjacent checks" — four families
out of the fifty-odd ruff ships.  Everything ruff could usefully say
about this module (bugbear, comprehensions, pyupgrade, pylint,
ruff-specific rules) is switched off along with the handful of rules
that genuinely fight Python 3.6.  The formatter was never enabled at
all, so `dataclasses.py` and `test.py` were formatted by hand and by
habit.

The narrow selection also left a self-inflicted inconsistency.  The
config explains at length that flake8-builtins is *not* selected and
that the ten `# noqa: A002` comments in `dataclasses.py` are "kept as
documentation of where that shadowing is intentional" — but with `A`
deselected those comments are, to ruff, ten unused-noqa violations
waiting for `RUF100` to be enabled.  Documentation the linter would
flag as dead is documentation with a short shelf life.

Underneath all this sits the real constraint, which the config stated
but did not enforce: ruff's oldest expressible target is `py37`, and
this module must run on 3.6.  `target-version = "py37"` silences every
rule gated on 3.8 and later, but it explicitly *permits* the rules
gated on exactly 3.7 — the one-version gap where the danger actually
lives.  Nothing in the config acknowledged that gap.

## Impact

- Real defects in the classes ruff covers (mutable default arguments,
  loop-variable rebinding, redundant `getattr`, ...) go unreported.
- Formatting is unenforced, so it drifts one commit at a time.
- The `# noqa: A002` comments are dead weight the moment `RUF100`
  is switched on.
- The 3.6 floor is protected only by the coincidence that the four
  selected families contain no version-gated rewrites.  Selecting one
  more family, or ruff adding a rule to an existing one, would have
  removed that protection silently.

## Resolution

Inverted the approach: select broadly, then answer each conflict
individually.

`select` now names 34 rule families explicitly (F, E, W, I, N, UP, S,
B, A, C4, SIM, RET, PERF, FURB, PL, RUF, ...).  Naming families rather
than `ALL` keeps the anti-drift property the original config was after
— a new family in a future ruff release does not switch itself on —
and CI now pins `ruff==0.16.1` so that new rules *within* a selected
family arrive as a deliberate bump rather than on an unrelated PR.

The 3.6 floor is handled in three layers, all documented in
`ruff.toml`:

1. `target-version = "py37"` covers everything gated on 3.8+ (PEP 585
   generics, PEP 604 unions, walrus, positional-only parameters,
   parenthesized context managers, nested same-quote f-strings).
2. The rules that sit in the 3.6/3.7 gap are ignored by code, each
   with its reason next to it: `UP022` (`subprocess` `capture_output=`
   is 3.7+), `UP036` (would strip the `sys.version_info` fallbacks as
   dead code) and `FURB162` (`datetime.fromisoformat` is 3.7+).  A
   probe against ruff 0.16.1 confirmed those three are the complete
   set at this target.
3. flake8-future-annotations (`FA`) is never selected, and the config
   says why in as many words: `from __future__ import annotations`
   only exists from 3.7, and unlike the rules above it has no version
   gate to lean on.  It is the one family that is unsafe here by
   construction.

The 3.6 job in `.github/workflows/tests.yml` remains the backstop for
anything ruff cannot know is too new.

The remaining ignores are either the formatter's business (`E501`,
`ISC001`) or the cost of staying diffable against CPython's
`dataclasses.py`: `__all__` and `__slots__` ordering, `SIM102`/`SIM108`
(upstream's nested `if`s carry explanatory comments between them),
elif-after-return, and the pylint branch/argument-count metrics —
`_process_class` is 29 branches of table-driven logic upstream, and
`@dataclass()` takes eleven arguments by API contract.  `test.py` gets
per-file ignores for its harness idioms: prints, global pass/fail
counters, blind excepts, and the `x == x` comparisons that are the
point when testing `__eq__`.

Families left out entirely (FA, TC, ANN, ARG, SLF, PTH, C90, PYI,
D, EM, TRY, COM, ...) are listed in the config with one line each on
why, so the next person does not have to rediscover it.

One-off deviations now carry a `# noqa` at the site instead of a
blanket ignore — the UPPER_CASE sentinel classes (`N801`), the
`KW_ONLY_seen` flag (`N806`), the arguments and locals named after
builtins (`A001`, `A002`), the `setattr()` calls mypy requires
(`B010`), the `exec()` that generates the methods (`S102`), and the
3.6-only `import ctypes` fallback (`PLC0415`).  `RUF100` flags each of
them the day it stops being needed.  This also resolves the
inconsistency above: with flake8-builtins selected, the pre-existing
`# noqa: A002` comments are load-bearing again rather than dead.

The formatter is enabled, with `quote-style`, `indent-style`,
`line-ending` and `skip-magic-trailing-comma` spelled out rather than
defaulted, so a future ruff changing a default cannot reformat the
module unasked.  `docstring-code-format` is off: the docstrings are
CPython's, ASCII tables and code samples included.  Running it cost
two wrapped lines, two f-string quote flips and a handful of blank
lines — the sources were already close to ruff-formatted.

Markdown is excluded (`extend-exclude = ["*.md"]`).  ruff 0.16 formats
fenced code blocks inside Markdown, and `ruff format .` would
otherwise have rewritten eleven files in this issue archive, which
quotes upstream CPython and pre-fix snippets verbatim.

The findings ruff was right about were fixed rather than ignored:

- `[self_name] + _init_params` → `[self_name, *_init_params]` (RUF005)
- `getattr(cls, "__doc__")` → `cls.__doc__` (B009)
- two yoda conditions in `test.py` (SIM300)

`B010` was *not* taken: `newcls` is typed as `type`, which has no
`__setstate__` and whose `__getstate__` has a different signature, so
`mypy --strict` rejects the direct assignment.  The `setattr()` calls
stay, with a comment saying why.

CI now runs `ruff check .` and `ruff format --check --diff .` over the
whole tree instead of naming the two source files, which the Markdown
exclusion makes safe.

Verification: `ruff check`, `ruff format --check`, `mypy --strict` and
the suite (239/239) all green on 3.11.  The development environment
has no Docker daemon and no 3.6 interpreter, so 3.6 could not be run
locally; as a stand-in, `vermin` was run against the sources before and
after and the reported feature requirements diffed — the only addition
is "generalized unpacking requires 3.5", from the RUF005 fix, which is
below the floor.  The 3.6 and 3.7 CI jobs are the authoritative check.
