# dataclasses.py lacks an attribution/license header

## Severity: LOW

## Description

`dataclasses.py` is a derivative of two upstreams:

- Eric V. Smith's dataclasses backport
  (https://github.com/ericvsmith/dataclasses/), Apache License 2.0
- CPython's `Lib/dataclasses.py` (PSF License), from which the
  post-3.7 features were backported

The repository carries an Apache 2.0 `LICENSE` file (commit 3b3944f:
"Apache License just like the original we have derived from"), but the
source file itself contains no header — it starts directly with
imports.

The readme's recommended distribution model is **vendoring**: copying
the single `dataclasses.py` into another project.  A vendored copy
travels without the repository's `LICENSE` and readme, so the file
itself is the only place attribution can reliably survive.  Apache 2.0
§4 also requires derivative works to retain attribution notices.

## Resolution

Added the header at the top of `dataclasses.py` as proposed, noting
both upstreams (ericvsmith backport, Apache 2.0; CPython, PSF
License), the Apache 2.0 license of this derivative, and the source
repository URL so a vendored copy can be traced back.  Wording says
"Python 3.6+" since the module now supports 3.6 and later (issue 9).
